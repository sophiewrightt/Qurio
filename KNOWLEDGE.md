# Knowledge and levels

The active reward policy is **5 Knowledge per correct scored answer, 200 Knowledge per level, starting at Level 1 with 0 Knowledge**. This supersedes the old `20 + correct * 5` completion reward and participation XP. Scored in-lesson checks count too; open-ended opinions, random landing predictions, reveals and merely completing a lesson do not. A failed final challenge retains Knowledge from correct answers without granting lesson completion or world rewards. Replaying a lesson is a new earning attempt.

`data/knowledge.ts` owns the constants and immutable ledger functions. `KnowledgeProvider` connects `LessonQuiz` and explicit graded checks to App's per-lesson-visit question-key deduplication. Never award from an answer's green display state: a quiz also highlights the correct option after an incorrect choice. New scored checks should call `useKnowledge()` only when accepting the correct answer, with a stable, unique question key, or pass explicit `knowledgeKey`/`isCorrectAnswer` to `AnswerButton`. Keep existing answer locks and interaction gates.

App holds earned total, last presented total, Quanta and pending level celebrations. Home scrolls the bar into view after loading/world overlays clear and animates from the last presented amount. `XPBar` pauses at each 200-point boundary; settling that boundary credits exactly 20 Quanta and queues its level. `LevelUpModal` shows a shiny golden orb and the new number. Dismissing the modal resumes any remaining progress. Interrupted animations cancel, leaving unpresented gains for the next Home visit. Functional ledger updates prevent duplicate payouts; repeated dismissal cannot skip the next celebration.

The top-right settings control displays the locally entered Guest / Tester username, a bold purple level number beneath it and “tap to see settings”. It opens a right-side settings drawer with Profile & birthday and Leave this session. It no longer repeats the particle avatar. The displayed level follows presented Knowledge, preserving level-up sequencing. Avatar greetings wait until the Knowledge/reward sequence and active tour have finished. The wardrobe receives the same live Knowledge and Quanta totals. See `ONBOARDING.md`; this name is not an authenticated account.

All of this remains **session-only prototype state**, not secure account persistence. Nothing is written to Supabase. When authentication is implemented, award answers, debit lives, validate quiz attempts and grant level rewards server-side with per-user idempotency keys; never trust client totals for purchases or progression. Preserve unrestricted prototype access until that backend exists.

Checks: `node tests/knowledge.cjs`, all `tests/*.cjs`, `npm run typecheck`, Expo exports and browser checks. Unit coverage includes failed quizzes, wrong-first/rapid taps, replay, stale callbacks, exact and multiple level boundaries, duplicate payouts/dismissals, and animation cancellation.
